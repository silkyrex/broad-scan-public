# broad-scan CLI

Two modules. Same DB (`broad-scan.db`). VPS is source of truth.

```
python -m scanner.cli   -- scan + prospect pipeline
python -m locker.cli    -- locker room (EMA4, positions, history)
```

## Daily flow

```bash
# Morning: review Discord post, add tickers to prospects
python -m scanner.cli prospect-session

# Anytime: check locker room live EMA4 status
python -m locker.cli show

# Periodic: review prospects and graduate or drop
python -m scanner.cli promote-session   # all prospects, oldest first
python -m scanner.cli drop-session      # stale only (14d+, no RSI signal)

# One-off: promote or drop a specific ticker
python -m scanner.cli promote COHR
python -m scanner.cli drop-prospect COHR
python -m scanner.cli exit COHR         # remove from Locker Room

# View current state
python -m scanner.cli list-prospects
python -m scanner.cli list-locker
```

## Commands

**`prospect-session`**
Shows today's scan list (RSI-D, RSI-W, ATH, SCTR). Type tickers one per line to add to prospects.

- If you type a ticker with no notes, auto-generates a thesis note via yfinance + Haiku and populates `notes_technical` from the scans table.
- If you append notes inline (`COHR photonics tailwind`), those are used as-is and `notes_technical` is still populated automatically.
- Duplicate tickers are flagged and skipped -- nothing is inserted twice.
- Blank line or `done` to finish. Tickers already in prospects marked with `*`.

**`add-prospect TICKER [TICKER ...] [--source SOURCE] [--notes NOTES] [--bucket {prospect,buy_and_hold}]`**
Batch add. Source defaults to `sc_workbench`. Bucket defaults to `prospect` (momentum / breakout watch); use `--bucket buy_and_hold` for long-term thesis adds (e.g. 200w SMA reclaim). Does not auto-generate notes. Source conventions in use:

| Source | Meaning |
|---|---|
| `sc_workbench` | StockCharts Scan Workbench RSI >= 67 (default) |
| `52w_high`, `ath`, `rsi_daily`, `rsi_weekly` | From scanner.run yfinance signals |
| `position_scan` | Manual 200w SMA reclaim / hold thesis |
| `news`, `chart`, `tip` | Free-form manual entries |

Example: `python -m scanner.cli add-prospect OXY --source position_scan --notes "200 week sma" --bucket buy_and_hold`

**`refresh-technical`**
Refreshes `notes_technical` for all active prospects from the latest scans table data (last 7 days). Runs automatically at 9:05 AM M-F via cron. Run manually anytime to update signal tags after a new scan lands.

Format: `SCTR 99.5 | RSI-D | RSI-W | RSI-M | ATH | 52w-high | 12w-high`

**`promote-session`**
Interactive review of all active prospects, sorted oldest first. For each prospect shows notes + technical tags + age + stale flag. Commands: `p` = promote to Locker Room, `d` = drop, Enter = skip, `done` = quit. Pushes DB to VPS if any changes made.

**`drop-session`**
Same as promote-session but shows only stale prospects (14+ days old with no RSI tag in notes_technical). Useful for periodic cleanup. Commands: `d` = drop, `p` = promote, Enter = skip, `done` = quit.

**`drop-prospect TICKER`**
Drop a single prospect directly without a session.

**`promote TICKER`**
Promote a single prospect to the Locker Room directly without a session.

**`exit TICKER`**
Mark a Locker Room name as removed. Timestamps the exit.

**`list-prospects [--bucket {prospect,buy_and_hold}]`**
Shows all active prospects. Each entry shows ticker, age in days, bucket, and a ⚠ stale flag if 14+ days with no RSI signal. Notes and notes_technical on separate lines. Use `--bucket` to filter.

**`list-locker`**
Shows active Locker Room names with promoted date, date of weekly RSI cross, and weeks in the run.

**`prospect-sc-sync [--bucket {prospect,buy_and_hold}] [--clear] [--dry-run]`**
Pushes the active prospects in the chosen bucket to the matching StockCharts chartlist (`prospect` → `[0000]` listNum 25; `buy_and_hold` → `[0102]` listNum 26). Default mode is additive. `--clear` wipes the SC list first (replace mode). `--dry-run` prints what would be pushed without calling SC.

Examples:
```bash
# replace [0102] with the current buy_and_hold set
python -m scanner.cli prospect-sc-sync --bucket buy_and_hold --clear

# preview without touching SC
python -m scanner.cli prospect-sc-sync --dry-run
```

## Notes and enrichment fields

Each prospect has two note fields and five enrichment fields:

| Field | What goes in | Written by |
|---|---|---|
| `notes` | Plain sentence thesis -- the business catalyst driving momentum | You (inline) or auto-generated by Haiku via yfinance |
| `notes_technical` | Signal tags: SCTR, RSI-D/W/M, ATH, 52w-high | Auto from scans table on add; refreshed daily by `refresh-technical` |
| `sector` | Sector from yfinance (e.g. Technology, Industrials) | Auto on add via yfinance |
| `industry` | Industry from yfinance (e.g. Semiconductors) | Auto on add via yfinance |
| `market_cap` | Market cap in dollars | Auto on add via yfinance |
| `beta` | Beta vs market | Auto on add via yfinance |
| `short_pct_float` | Short interest as % of float | Auto on add via yfinance |

## Editing an existing prospect

There is no `update-prospect` command. To change fields on an existing row, update the DB directly:

```bash
sqlite3 broad-scan.db "UPDATE prospects SET notes='new thesis' WHERE ticker='OXY';"
sqlite3 broad-scan.db "UPDATE prospects SET source_scan='position_scan' WHERE ticker='OXY';"
```

Column names: `source_scan`, `notes`, `notes_technical`, `bucket`.

## Locker Room commands (`python -m locker.cli`)

**`show`** (alias: `locker`)
Fetches live prices for all active tickers. Displays:
- Regime block (21 anchors, EMA4-based RISK-ON/MIXED/RISK-OFF) + scan regime (BULL/CHOP/BEAR)
- OPEN rows: `[Xsh] | R-multiple | day% | stop-cushion | brief● | days-held`
- VALID/WATCH/DROP rows: `ticker[↑] | [Nd] | ^N/vN | day% | rN | -N%h | buzz×N`
  - `↑` on ticker = exit-d1 at last close but reclaimed EMA4 live intraday
  - `[Nd]` color = zone: green=VALID, yellow=WATCH, red=DROP, dim=NO SIGNAL
  - `^N` / `vN` = N% above / below 4 EMA (live, not last close)
  - `rN` = RSI-D. Sweet spot 60-75.
  - Sorted by setup score within each section: EMA tightness + RSI range + 52w proximity. Best setups top.

**`pick`**
Regime-aware entry brief. Run after `locker` when considering an entry. Scores all VALID names by setup quality, searches KB for prior outcomes per ticker, calls Sonnet for a 3-4 sentence brief.

Output: best setup + why + entry trigger + KB note. Sizing cap: 25% BULL / 15% CHOP/BEAR. Prefers toby_status=reclaim over hold.

```bash
locker pick
# 🎯 locker pick  BEAR regime · max 15%
# HPE is the top setup: tight EMA reclaim, RSI 66, 4% from 52w high...
```

**`refresh [TICKER] [--live]`**
Recalculates EMA4 for all active names (or one ticker). Without `--live` uses last close price. With `--live` uses current intraday price. Logs changes to `locker_history`. Runs automatically on the VPS at 12 PM (live) and 1:25 PM (close) M-F.

**`open TICKER shares entry stop [--broker NAME] [--size full|pilot] [--setup 4ema_reclaim|day2_entry|add_on|manual]`**
Logs a position open in the `positions` table. Auto-calculates `r_risk` from `shares × (entry - stop)`. Defaults: broker=alpaca, size=full, setup=4ema_reclaim. Ticker must be in active locker room first.

```bash
python -m locker.cli open SATL 100 45.20 42.00 --size pilot --setup 4ema_reclaim
```

**`close TICKER [--price X] [--reason TEXT]`**
Closes the open position. Fetches MFE and MAE from yfinance since entry date. Prints P&L, MFE, MAE.

**`stop TICKER --price X`**
Moves the stop price on an open position. Logs old → new to `locker_history`. Use when advancing from phase 1 (hard stop) to phase 2 (breakeven) or phase 3 (trail).

```bash
python -m locker.cli stop SATL --price 44.00   # move to breakeven
```

**`scale TICKER shares --entry X [--stop X] [--setup add_on|day2_entry]`**
Adds shares to an existing open position. Blends the new fill into a weighted-average entry price. Updates `r_risk` with the new total exposure. Logs the add detail (old/new shares, prices) to `locker_history`. Does not create a second row — one open row per ticker.

```bash
python -m locker.cli scale SATL 50 --entry 46.00 --setup day2_entry
```

**`refresh-positions`**
Updates MFE and MAE for all open positions from yfinance. Runs automatically on the VPS at 1:30 PM M-F.

**`stale [N]`**
Shows names N+ days in locker with no reclaim signal. Default threshold: 14 days (2 trading weeks).

**`history TICKER`**
Full event log for a ticker -- added, opened, closed, every EMA4 status change.

**`note TICKER "text"`**
Updates the thesis note for an active locker room ticker. Logs the old and new note to `locker_history`. Pushes DB to VPS. Use when the thesis evolves after promotion.

**`pull [TICKER]`**
Fetches and stores technicals: price, RSI D/W/M, 52w high %, ATH %, and SMAs (10/20/50/100/200) from yfinance. Runs on all active locker names if no ticker given. Gracefully falls back to daily closes for tickers with insufficient weekly/monthly history (recent IPOs).

```bash
python -m locker.cli pull CBRS    # single ticker
python -m locker.cli pull          # full locker refresh
```

**`enrich [TICKER]`**
Backfills sector, industry, market_cap, beta, short_pct_float from yfinance. Runs on all names with missing sector if no ticker specified.

## Position ledger (`pos`)

Separate CLI at `locker/pos.py`, invoked via `~/.local/bin/pos`.

**`pos`** — full book: all open positions with live yfinance prices, P&L, stop cushion, and phase.

```
BOOK — Tue May 19 2026 | 2 open | unrealized: +$480 (+3.1%)

  HIMX      100sh @ $18.10  stop $17.50  10.2% cushion  5d  p1  [pilot]
            NOW $19.29  P&L +$119 (+6.6%)

  AXTI       80sh @ $14.20  stop $13.10  15.6% cushion  8d  p2
            NOW $15.15  P&L +$76 (+8.4%)
```

Stop phase is derived from stop vs entry:
- `p1` — stop below entry (hard stop)
- `p2` — stop near breakeven (within 0.5% of entry)
- `p3` — stop above entry (trailing)

**`pos TICKER`** — single position detail. Shows a vertical ASCII price ladder with ENTRY, NOW, and STOP markers, cushion %, and P&L inline. Below the chart: a full OPEN box with ticker, broker, size, phase label (hard stop / breakeven / trail), max loss, and R.

```
     $19.30  ─── ENTRY / NOW  -$3
             │
             │   8.6% above stop
             │
     $17.76  ─── STOP     max loss $462

┌─ OPEN ────────────────────────────────────────┐
│ Ticker   HIMX  300 sh  0d held                │
│ Broker   ibkr  [pilot]  setup: manual         │
│ Entry    $19.30  (2026-05-19)                 │
│ Live     $19.29                               │
│ P&L      -$3 (-0.1%)                          │
│ Stop     $17.76  (Phase 1 / hard stop)        │
│ Max loss $462                                 │
│ To stop  $459 (7.9% below live)               │
│ R        $462                                 │
└───────────────────────────────────────────────┘
```

## DB structure

```
locker_room   = staging. watching for the entry signal.
positions     = you bought it. lives in your broker account.
```

Every position links back to a `locker_room` row via `locker_room_id`. Full schema in `CLAUDE.md`.

## What promotes automatically

When you run `promote` or `promote-session`:
- Prospect notes copied to locker_room
- EMA4 status fetched live
- sector, industry, market_cap, beta, short_pct_float fetched from yfinance
- `added` event logged to locker_history
- DB pushed to VPS

`positions` row is created only when you actually enter the trade via `buy TICKER` (or `locker open` for manual override).

## Entering a position: `buy TICKER`

Primary entry command. Auto-sizes from regime + equity, then logs the position.

```bash
buy NVDA
```

Output:
```
  Regime: BULL
  Equity: $50,000 x 20% = $10,000
  NVDA:   $131.42  ->  76 sh

  Stop price: 128.00

  76 sh NVDA @ $131.42, stop $128.00  R=$259 -- proceed? [y/N]
```

- Fetches regime via `bin/regime-check.py` (BULL/CHOP/BEAR)
- Reads equity + `regime_entry_pct` from `config/sizing.json`
- Fetches last close via yfinance
- Prompts for stop, then confirmation
- Runs wash sale check (30-day lookback in `positions` table) before prompting
- On confirm: inserts into `positions`, logs to `locker_history`, captures to KB, pushes DB to VPS

**Overrides** (skip any auto step):
```bash
buy NVDA --entry 131.00 --shares 80 --stop 127.50
buy NVDA --setup day2_entry --size pilot
```

**Manual override** (skip auto-sizing entirely):
```bash
python -m locker.cli open NVDA 76 131.42 128.00
```

Ticker must be in active locker_room before `buy` can log a position.

## Locker Room rhythm

| When | Command | Why |
|------|---------|-----|
| Session start | `pos` | Full book with live P&L before any decisions |
| Anytime | `locker show` | Always live -- see where each name stands right now |
| Thesis changes | `locker note TICKER "new thesis"` | Update the story, log the change |
| 4 EMA reclaim triggers | `buy TICKER` | Auto-size + wash sale check + log position entry |
| Scaling in | `locker scale TICKER shares --entry X` | Add shares, blends avg entry |
| Stop moves | `locker stop TICKER --price X` | Advance phase 1 → 2 → 3 |
| Exit | `locker close TICKER --price X` | Close the position, prints P&L |
| New ticker | `locker technicals TICKER` | Populate technicals after `locker add` |
| Weekly | `locker stale` | Identify names fading out, consider removing |
