# broad-scan

Stock picking process -- from scan universe to entry decision.

## Pipeline

```
Broad Scans
    │
    ▼
Prospects  (interest, no conviction yet -- not ready to trade)
    │
    ▼ auto-promote (post-close, 4 gates) OR manual locker add
    ▼
Locker Room  (promoted, dialed in, ready to trade)
    │  VALID = above 4 EMA, wait for trigger
    │  WATCH = exit-d1, one more day
    │  DROP  = exit-d2, remove
    ▼
Entry
```

Daily focus is the Locker Room. Broad scans feed prospects; auto-promote moves qualifying names to the locker every night without manual input.

## Daily workflow

Almost everything runs automatically. Your one action is curation.

**Automated -- VPS (your-vps), no action needed:**
- **6:35 AM M-F** -- SC Workbench fetch + Gmail ingest + yfinance signals + Discord post to `#scans` + KB capture
- **1:05 PM M-F** -- SC close email ingest + yfinance close signals + Discord post + KB capture (canonical signal)
- **1:05 PM M-F** -- auto-promote: 4-gate check (2+ signals, above EMA4, not in locker, regime flag) → Discord summary to `#signals` + KB capture
- **1:10 PM M-F** -- EOD close report + SC weekly charts to Discord (Fridays also post EOW report)
- **1:15 PM M-F** -- sync active prospects to SC chartlists `[0000]` and `[0102]`
- **12:00 PM M-F** -- locker EMA4 refresh (live price -- intraday read); EMA4 status changes → KB
- **1:25 PM M-F** -- locker EMA4 refresh (official close price); EMA4 status changes → KB
- **1:20 PM M-F** -- refresh `notes_technical` for all active prospects from latest scans
- **11:00 PM daily** -- dump prospects + locker_room to `backup/curation.sql`, commit + push to GitHub
- **11:35 PM daily** -- KB ingest: new prospects + locker_room rows → KB via Supabase

**Your one manual step (anytime after the Discord post):**
```bash
python -m scanner.cli prospect-session
```
Pulls fresh DB from VPS, shows today's scan list, lets you add tickers. Auto-generates a thesis note (via yfinance + Haiku) and technical tags (SCTR, RSI signals) for each ticker you add. Pushes DB back to VPS when done.

## Notes fields

Each prospect has two note fields:

| Field | What | Written by |
|---|---|---|
| `notes` | Plain sentence thesis -- the business catalyst | You (inline) or auto-generated by Haiku |
| `notes_technical` | Signal tags: SCTR, RSI-D/W/M, ATH, 52w-high | Auto from scans table, refreshed daily |

## StockCharts scan query

```
[TYPE = STOCK] AND [COUNTRY = US] AND [DAILY SMA(1,DAILY VOLUME) > 300000]
AND [DAILY CLOSE >= .2] AND [GROUP IS NOT ETF] AND [EXCHANGE IS NOT OTCMKT]
AND [ [DAILY RSI(14) >= 67] OR [WEEKLY RSI(14) >= 67] ]
```

**Two scanners, two jobs:**

| Scanner | Threshold | Job |
|---------|-----------|-----|
| StockCharts (`sc_import.py`) | RSI >= 67 | Wide universe -- watch zone, adds SCTR |
| yfinance (`scanner/run.py`) | RSI crosses 70 | Confirmed signal -- momentum triggered today |

67 = watch zone. 70 cross = trigger. Names in both = evaluate for prospects or locker.

**Bucket routing:** `prospect` (momentum watch) syncs to SC `[0000]`. `buy_and_hold` (long-term thesis, e.g. 200w SMA reclaim) syncs to `[0102]`.

## Locker Room

Once a prospect is promoted it enters the Locker Room. Run `locker show` anytime -- it fetches live EMA4 for all active tickers in one batch call.

```bash
python -m locker.cli show                        # live EMA4 + position state
python -m locker.cli reclaim                     # 4 EMA reclaim status (3-condition trigger)
buy TICKER                                       # log position entry (auto-sizes + wash sale check)
python -m locker.cli open TICKER shares entry stop  # manual entry log (override)
python -m locker.cli close TICKER                # log exit
python -m locker.cli stale [N]                   # names N+ days, no reclaim (default 21)
python -m locker.cli history TICKER              # full event log
python -m locker.cli refresh [TICKER]            # manual EMA4 refresh
```

Or via the bash UX wrapper at `bin/locker` (symlinked to `~/.local/bin/locker`):

```bash
locker                # default view: regime block + locker names + position flags
locker reclaim        # 4 EMA reclaim trigger check (used at 12:30 PT window)
locker pending        # new scan entries from last 7 days
locker sync           # push locker_room → StockCharts [0108]
locker add TICKER     # add ticker (fires research agent async)
```

When you promote via `promote-session`, EMA4 + sector/enrichment are fetched automatically on the spot.

### Regime block

The top section of `locker` output. Live yfinance pull on every call -- no cache.

| Category | Tickers |
|----------|---------|
| EQUITY | SPY, QQQ, IWM, DIA, EEM |
| BONDS | TLT, IEF, HYG |
| COMMOD | GLD, SLV, USO, CPER |
| CURR | DXY, EUR (EURUSD=X), GBP (GBPUSD=X), JPY (USDJPY=X) |
| CRYPTO | BTC, ETH, XRP, SOL |
| RISK | VIX |

**Combined state line:** `state: RISK-OFF / MIXED / RISK-ON` -- computed from EQUITY anchors only (3-4 below EMA4 = RISK-OFF, 0 below = RISK-ON, 1-2 below = MIXED). Shown after the ticker list.

**Note on JPY:** displayed as USDJPY -- ▲ EMA4 means dollar strengthening, not yen strengthening.

**Failure handling:** if yfinance times out or returns no data, prints `regime: fetch failed` instead of a blank section.

**Config:** `config/regime_anchors.json` -- add or remove anchors here. No code change needed.

## KB Integration

Every decision in the pipeline fires a thought to KB (semantic memory at your-vps:8000):

| Event | Trigger | What's captured |
|---|---|---|
| Morning scan post | `post_discord.py` auto | Tickers by signal type + top SCTR |
| EOD canonical close | `post_discord_close.py` auto | ATH/52W/RSI-D/RSI-W tickers + SCTR |
| auto-promote | `auto_promote.py` auto | Ticker, signal categories, EMA4 pct, regime flag |
| EMA4 status change | `locker refresh` auto | Ticker, from/to status; RECLAIM flagged as P1 trigger |
| add-prospect | CLI | Ticker, thesis, sector, bucket |
| drop-prospect | CLI | Ticker, reason |
| promote to locker | CLI | Ticker, EMA4, sector, mktcap |
| locker exit | CLI | Ticker, reason |
| open position | CLI | Entry, stop, shares, setup, R-risk |
| close position | CLI | Exit, P&L, MFE, MAE, reason |

Query examples: `"show me all RECLAIM events this month"`, `"tickers I dropped and why"`, `"positions closed with negative P&L"`.

Positions opened by Alpaca automation (not CLI) are not yet in KB -- see TRA-XXX.

## DB

Single SQLite file (`broad-scan.db`). VPS is source of truth. Mac pulls on `prospect-session` start, pushes after.

Tables: `scans`, `prospects`, `locker_room`, `locker_history`, `positions`, `schema_migrations`.

Schema changes go in `migrations/` as numbered `.sql` files. They run automatically on deploy via `db/init.py` -- no manual SSH needed.

## Paper Agent

A mechanical parallel track that runs the same strategy without discretion.
You run the hybrid (judgment + scans). The agent runs autonomously. Compare over time.

**Automated -- VPS (your-vps):**
- **7:05 AM M-F** -- checks exits on open positions, enters fresh 4 EMA reclaims from today's broad-scan universe, posts summary to Discord `#paper-lab`

**Entry gates (all 3 must pass):**
1. SCTR >= 75 (from sc_workbench)
2. 52w high or ATH signal today
3. Fresh 4 EMA reclaim -- prior close below 4 EMA, today's close above it

**Rules:** $500/position · 8% hard stop · 4 EMA break = exit · max 10 slots · `broker='paper-agent'` in positions table

```bash
python -m paper_agent.cli run      # manual daily run
python -m paper_agent.cli status   # open positions
python -m paper_agent.cli history  # closed P&L
python -m paper_agent.cli kill     # close all positions (kill switch)
```

## Structure

```
db/
  init.py        -- schema init + migration runner (called on every deploy)
  migrate.py     -- applies unapplied migrations from migrations/
migrations/
  001_*.sql      -- numbered schema migrations, auto-applied on deploy
config/
  regime_anchors.json  -- 12 regime anchor tickers (equity, bonds, commodity, currency, risk)
                          edit here to add/remove anchors; locker display reads this file live
bin/
  locker         -- bash UX wrapper (default view, sync, pending, reclaim, etc.)
  locker-sync    -- pushes locker_room → StockCharts ChartList [0108]
locker/
  cli.py         -- locker room commands (show, open, close, refresh, reclaim, stale, history)
  reclaim.py     -- 4 EMA 3-condition trigger check (locker reclaim)
backup/
  dump_curation.sh  -- nightly curation backup script (runs on VPS)
  curation.sql      -- latest dump of prospects + locker_room
scanner/
  cli.py              -- argparse entry point + single-step commands (add-prospect, promote, drop, exit)
  prospects.py        -- prospect data layer: enrichment, auto-notes, insert, staleness, DB sync
  sessions.py         -- interactive sessions: prospect-session, promote-session, drop-session
  kb.py              -- shared KB client (all KB captures go through here)
  run.py              -- yfinance signal engine (runs on VPS)
  post_discord.py     -- morning Discord post + KB capture (runs on VPS)
  post_discord_close.py -- EOD canonical close Discord post + KB capture (runs on VPS)
  auto_promote.py       -- post-close 4-gate auto-promote: 2+ signals + EMA4 + not-in-locker + regime flag
paper_agent/
  agent.py   -- core logic (find_candidates, enter_positions, check_exits, kill_all)
  cli.py     -- CLI (run, status, history, kill)
docs/
  pipeline.md         -- full pipeline diagram, cron schedule, buzz bridge, EOD/EOW reports
  infra.md            -- your-vps deploy chain, env vars, deploy keys, health checks
  cli.md              -- CLI commands reference
  scan-criteria.md    -- what qualifies a ticker at the scan stage
  prospects.md        -- criteria for scan → prospects and prospects → Locker Room
  locker-criteria.md  -- what makes a ticker Locker Room ready
  entry-rubric.md     -- entry and exit rules (4 EMA cross)
```
